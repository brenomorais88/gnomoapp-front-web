# i18n Strategy

This project keeps **all source code in English** while localizing **user-facing UI text**.

## Current language approach

- Default UI language: `pt-BR`
- Translation catalogs live in `messages/`
- Translation access utility lives in `lib/i18n/`

## Files

- `messages/pt-BR.ts` - current production UI texts
- `messages/en.ts` - placeholder for future expansion
- `lib/i18n/index.ts` - `t()` and catalog resolution

## How to add a new language

1. Create a new catalog file in `messages/` (example: `es.ts`).
2. Mirror the key structure from `pt-BR.ts`.
3. Register the language in `lib/i18n/index.ts`.
4. Use the same keys in UI code (no hardcoded user text).

## How to add new translation keys

1. Add the key to `messages/pt-BR.ts`.
2. Add the same key to other catalog files.
3. Consume with `t("section.key")` in pages/components.

## Team rule

- Keep code identifiers in English (files, folders, symbols, types, hooks, comments).
- Localize only user-visible messages.
- Prefer centralized keys over inline literals to keep multilingual support maintainable.
